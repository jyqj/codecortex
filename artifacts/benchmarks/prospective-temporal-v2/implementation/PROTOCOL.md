# P8-004 prospective temporal test v2

Status: revision 2 draft for independent review. The original draft is retained; two non-author interface findings are corrected before authoring or execution. No repository is selected, no new query or gold is authored, no run is authorized, and no TODO is closed by this draft.

This is a new, narrowly scoped experiment for the original P8-004 sealing and anti-overfitting work. It freezes the final local candidate and all measurement choices **before** fresh source-task authoring. It is not the older v1 restricted-custody protocol and does not establish a reusable secret test set. The old 117 would-be held-out records remain 72 known-exposed at minimum, 45 unknown, and zero certified clean. Their decisions, checkers, corpus and histories stay unchanged.

`protocol.json` is the machine-readable normative plan. This document explains its implementation and evidence boundaries. In a conflict, stop for prospective review before drafting or running; do not choose whichever text produces a passing result. `locks.template.json` has deliberate nulls: they block authoring/execution and are not defaults.

## Original authority and scope

The original task depends on P8-003, requires a production check for gold paths/question dictionaries, one frozen-config held-out execution, no translation/paraphrase leakage or post-regression label repair, and related old regressions. The original 09-BENCHMARK fixes source/query/gold/build/config/environment locks, primary/supporting source review, hard negatives, family-based accounting and honest invalid/inconclusive results. It does not prescribe an external institution or an exact number of questions for this particular task.

The later v1 protocol does prescribe independently restricted custody. We preserve that stronger route and explicitly do not claim to satisfy it with agent instructions, shared storage or a new public Git blob. Here the protection is the observable temporal ordering of immutable candidate selection before fresh question creation, followed by no tuning of that arm. A shared service can still technically expose data; this is disclosed, not disguised as an ACL.

The experiment is local-only. No live/paid semantic provider, private-source upload, full G8, 100k, general semantic benefit or release-quality certification is authorized or inferred.

## Fixed experimental choices

Use one small licensed public Go or Python repository never used by any **known metadata-identified** DEV, OCE or historical held-out repository. Exact repository/commit and known-exclusion manifest must be frozen before authoring. Record alias/fork/mirror/copied-module checks and every metadata candidate rejected. Do not choose by retrieval results. Unknown historical identities or unread old-body relationships remain disclosed limitations.

Reserve twelve monotonically numbered source-task families before drafting. Ten are answerable and two have independently proved no-answer under explicit source/scope/version. Every family has an English original, its Chinese translation, an English paraphrase and a Chinese paraphrase: 48 native rows. They share gold/scope and remain one component. Required family coverage is 3 API/symbol, 3 behavior/semantic, 2 configuration/error, 2 multi-step call-chain, and 2 no-answer. These are this experiment's prospective design choices, not newly attributed original-task thresholds.

Each answerable family includes at least one real, source-located, wrong but lexically closer/plausible hard negative. At least two English original semantic questions must satisfy the exact raw-token zero-overlap predicate in protocol.json against all accepted gold evidence/path/symbol tokens. The independent reviewer also checks ordinary natural phrasing. A Chinese/English script difference alone cannot supply this English requirement. Token sets and intersections are retained; the label does not claim semantic distance or whole-repository zero overlap.

All twelve families and variants are test-only under the new `prospective_temporal_test_only` scheme. The native wire schema retains its existing `holdout` field value; distinct annotations identify this scheme. We do not route it through the v1 hash split or use `--custodian` to assert an unavailable boundary. No DEV is moved into test. Any discovered same-task component is merged and disclosed before the data seal; a merged sample smaller than twelve does not meet this planned twelve-component experiment. There is no silent replacement, quota hunting or salting.

Preserve the already fixed runtime values: top-k10, repetitions3, warmup0, timeout30000ms, seed20261003, concurrency1. Run candidate local-default and rg baseline, in that order. The input JSONL stays in family order with the four variants above. Preserve the exact288-entry dispatch schedule and verify it against the actual64-bit runner using synthetic inputs before authoring. ## One execution and honest failure handling

Start each arm from the same pristine source and an empty per-arm index; do not call OS page cache cold. Use the exact frozen public MCP/declared baseline adapter, same inputs/budgets, and actual source/ready evidence. Verify every binary/helper/config/source lock before and after, and retain full raw, normalized hits, scopes/spans, statuses, lane/model absence, readiness/generation, request order, deadlines, errors and exit codes.

The first real scheduled query consumes the attempt. A later failure cannot produce a new best-of run, new candidate, edited gold or changed denominator. All missing rows are explicit; an incomplete/invalid measurement cannot pass. An infrastructure setup/download retry is allowed only if original evidence proves that no scheduled query was dispatched and all seals remain identical. If dispatch cannot be excluded, assume consumed. Product/measurement logic changes after body exposure require a future genuinely new test, not a retry on this one.

Readback, hash checking, raw-only replay, independently recomputing metrics and recovering original archived bytes are allowed because they issue no new product queries. Their evidence must say verification of the original attempt. A parser/scorer bug cannot be silently repaired by choosing a more favorable re-interpretation of this report.

## Reporting and final disposition

The unchanged native scorer supplies core scores. Report the exact native no-answer score and normalized_no_match+zero-hits results. Also retain raw empty-result/partial/error observations. The current normalizer derives NoMatch from a complete empty response, and the runner also converts Success+empty to NoMatch; this is original behavior and is not changed. Do not present that derived status as an explicit raw product refusal. A separately named raw_explicit_no_match column can rely only on a documented actual raw field. When none exists, record unsupported/null with the reason, not false or a fabricated true; this optional capability audit is not a new pass gate for004. Partial/error/missing responses cannot be reported as complete empty responses. Explicit schema/lock/infra failures retain their true invalid-measurement status rather than being called low quality.

Average repetitions and the four variants inside each source-task component, then give components equal weight. Report per-row outcomes, family deltas, query micro means and category denominators. Ten answerable and two no-answer components have separate applicable metrics. The pinned 10000-draw seed20261003 paired family bootstrap resamples complete components, preserving both arms/all repeated observations. With one purposively selected repo and twelve families, these are conditional exploratory precision summaries; they cannot establish broad release/generalization claims. Preserve insufficient-N or undefined outcomes as inconclusive.

Keep the original hard integrity requirements: no source/scope/version leakage, deterministic correctness and unchanged scorer goldens. The suggested0.01 nDCG and one-point PrimaryTop1 regression values are review triggers, not an invented automatic passing threshold. A valid poor or inconclusive quality result can be reported honestly while independently assessing the narrower sealing/anti-overfitting task. It does not accept the product for release or close later tasks by implication. Missing/invalid evidence blocks the corresponding integrity claim.

After the attempt, retire this test for confirmatory evaluation of any subsequently tuned candidate. Public disclosure may make every body known; that does not retroactively change the actual freeze chronology, but it ends future hold-out use. Do not relabel the old117 or this new test as v1 clean custody. Final original-task status remains a separate non-author decision after all actual evidence and hard dependencies exist.
