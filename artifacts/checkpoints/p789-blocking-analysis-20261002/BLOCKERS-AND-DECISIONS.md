## 0. 全局阻塞结构（先读这个）

tasks.json 的 `dependency_semantics` 明确：`depends_on` 为硬集成依赖；`conditional_dependencies` 仅在对应认证范围启用时生效，未启用的条件任务保持 todo/blocked/deferred，不算 done。

单一工程链：

```
P5-019(in_progress) → P5-020 → P6 全部(001~019) → P6-020
  → P7 全部(001~020) → P7-020
  → P8 全部(001~020) → P8-020
  → P9 全部(001~012)
```

结论：**P7/P8/P9 的全部 52 项在工程链上都被 P5-019/020 与 P6-020 阻塞**。本清单区分的是第二类阻塞——授权与决策阻塞，即工程链打通后哪些项可以直接做、哪些必须先等用户拍板。

暂停快照已明确的边界：无真实付费 provider 授权/调用；无真实 100k/holdout/Linux/发行认证；模板/合成 1k corpus 不冒真实仓、holdout 或 100k。

## 3. 需要用户决策的逐项清单

### D1 真实付费 provider 授权

- **决策问题原文**：是否授权真实 embedding/LLM API 调用？选择哪家 provider（任何 OpenAI-compatible 端点）、预算上限多少、有效期多久？
- **涉及任务**：`P7-018`（受授权真实 provider 小集认证，conditional：仅在获得明确授权及预算时执行；缺证据阻止相应 live 效果声明，不阻止已满足的 local 发布范围）、`P8-015`（真实语义效果发布认证，同 conditional）；受限波及 `P7-019` 质量腿、`P8-014`、`P8-020` live 声明。
- **不决策的后果**：P7-018/P8-015 保持 blocked/deferred（合规，不算失败）；所有 live 语义效果声明为空，发布只能走 local 范围。工程链不被卡死，但语义线的"质量证明"永远缺一角。
- **建议默认值**：本轮不授权，按 local 范围完成 P7/P8；如需 live 证据，后续做一笔小额单次授权（例如一家 provider、几十美元量级上限、仅公开合成语料），避免先决卡主线。

### D2 代码外发政策（P7-007 政策内容）

- **决策问题原文**：启用语义时，允许哪些内容外发到 provider 端点？仅查询文本、还是含检索到的源码片段？私有仓是否一律禁止外发？
- **涉及任务**：`P7-007`（默认无网络、日志无 key/源码、重定向不泄露认证——机制本地可做；政策内容决定默认配置与文档）。
- **不决策的后果**：P7-007 的机制可先实现，但默认配置与安装契约无法定稿，P8-018 文档同步会漂移；极端情况下可能做出与用户预期不符的外发默认值。
- **建议默认值**：默认无网络 + semantic.enabled=false；显式启用后仅外发查询编码所需文本，源码正文外发须逐项目 opt-in；日志与收据零 key、零源码原文。

### D3 真实多仓语料来源（P8-002/P8-003 关键链）

- **决策问题原文**：P8-002 的"真实多仓 native 语料"用哪些仓库？许可与使用方式如何登记？P8-003 外部兼容套件跑在哪些固定 commit 上？
- **涉及任务**：`P8-002`（题数/类别/语言/能力缺口透明）→ `P8-003`（外部兼容套件）→ `P8-004`（holdout 封存）→ 顺延整条 P8 关键链到 P8-013。
- **不决策的后果**：P8-001 之后整条关键链停摆——这是 P8 主线最早的外部阻塞点。合成/模板 corpus 依红线不得替代真实仓。
- **建议默认值**：公开 GitHub 仓库集（延续 09-BENCHMARK 已固定的 Flask `pallets/flask@22d9247`、cc-switch `farion1231/cc-switch@40cac1a` 先例，再补 2~4 个不同语言/规模公开仓），固定 commit 锁定 + 许可登记；外部题库走已固定的 oce-benchmark 路径作对照。

### D4 holdout 封存与反过拟合（P8-004）

- **决策问题原文**：holdout 由谁生成/保管、何时解封？回归后标签修改的复核人是谁？
- **涉及任务**：`P8-004`（translation/paraphrase 不泄漏，回归后不直接改标签保分）。
- **不决策的后果**：holdout 无法封存，反过拟合检查没有独立裁判，语义质量认证可被质疑为自证。
- **建议默认值**：生成期隔离（出题与调优不同语料/不同会话），holdout 文件由用户自行封存（不入仓），解封与改标签须用户确认。

### D5 100k 规模硬件与机器时段（P8-005 及规模系列）

- **决策问题原文**：完整规模 1k→100k 在本机（macOS）还是外部 runner 跑？可接受的连续机器占用是多少？soak 时段如何安排？
- **涉及任务**：`P8-005` → `P8-006/007/008`（曲线/并发/分层）→ `P8-010`（soak）。
- **资源估算**（依据 `docs/BENCHMARK.md` 实测与 `03-SEMANTIC.md` 口径）：
  - 现状：10k 冷建 17.9s（优化后 10.0s）、RSS 236.5 MB、55,617 符号；50k 冷建 49.6~121.8s、RSS 1182.6 MB、278,074 符号；50k 库"多百 MB"。
  - 100k 外推：冷建约 100~250s（超线性已修，留余量取 3~5 分钟）；峰值 RSS 约 2.4~3 GB；SQLite+FTS+索引约 1.5~3 GB；dense f32 向量（1024 维）文档级 100k 约 390.6 MiB，若 chunk 级 3~5 倍则 1.2~2 GB。
  - 磁盘总预算建议 **≥20 GB 余量**（含 evidence raw、历史 run 不被覆盖——P8-019 红线）。
  - 时间：完整规模矩阵 + 每层 ≥30 样本 + 尾延迟 ≥200 同类样本（09-BENCHMARK 口径）+ soak ≥24h，合计建议预留 **2~3 天机器时段**（可与开发错峰，夜间跑）。
- **不决策的后果**：P8-005 起的规模认证无法排期；若默认在本机跑，可能与用户日常占用冲突，或中途被暂停导致 soak 数据作废重跑。
- **建议默认值**：本机跑，夜間错峰；先 100k 单轮完整规模验证资源外推成立，再排 soak；若本机不可承受再议云 runner。

### D6 Linux 矩阵环境（P8-012）

- **决策问题原文**：MSRV 与平台冷构建矩阵在哪跑？本机 Docker（Linux 容器，非真实内核但工具链真实）、独立 Linux 机器、还是 GitHub Actions runner？或者明示收窄发布平台范围？
- **涉及任务**：`P8-012`（SDK blocker 解决或发布平台范围明确；缓存测试不替冷构建）→ 阻塞 `P8-013`、`P8-016` 平台腿。
- **不决策的后果**：P8-012 保持 blocked，P8 关键链末段（013→016→017→018→019→020）全部顺延；或被迫默认"仅 macOS"，需要明示声明而非沉默缺失。
- **建议默认值**：GitHub Actions 免费/自费额度跑 Linux 矩阵（cold build 必须无 cargo 缓存，符合 09-BENCHMARK 冷建口径）；若不批 CI，则在 P8-020 明示"发布平台范围 = macOS (darwin arm64)"。

### D7 发行口径（P8-019/P8-020 及 P7-020 报告形态）

- **决策问题原文**：本次发布范围按 local-only、完整（含 live 语义）、还是双轨报告收口？
