# Benchmark

## Current State

Fixture benchmark results are generated by `cargo test -p cc-eval -- benchmark_fixture` and written to `docs/benchmarks/latest.md`. A separate ignored real-workspace benchmark writes `docs/benchmarks/real_workspace_latest.md`. This document tracks what should be measured and baseline targets.

## Planned Metrics

### Indexing Performance

| Metric | Target | How to Measure |
|--------|--------|----------------|
| Index speed (files/sec) | >500 for tree-sitter languages | `time codecortex mcp --project-path <repo>` on first connect |
| Incremental reindex | <2s for 10 changed files | `cargo test -p cc-eval bench_incremental -- --ignored --nocapture` (see Incremental Indexing Latency below) |
| Memory (peak RSS) | <512 MB for 10K file repo | `time -l` or `/usr/bin/time -v` |

### MCP Tool Latency

| Tool | Target p95 | Notes |
|------|-----------|-------|
| status | <50ms | Reads cached metadata |
| search | <200ms | Ranked FTS5 + grep fusion |
| context | <500ms | Multi-symbol extraction + source |
| node | <100ms | Single symbol lookup |
| explore | <300ms | Batch symbol inspection |
| trace | <500ms | BFS path finding + source bodies |
| relations | <100ms | Direct edge query |
| impact | <500ms | BFS reverse-caller expansion |
| architecture | <300ms | Aspect-dependent aggregation |
| graph_query | <200ms | Cypher subset execution |

### Retrieval Quality

| Metric | Definition | Target |
|--------|------------|--------|
| Recall@5 | Fraction of expected symbols in top-5 search results | >0.7 |
| MRR | Mean reciprocal rank of first correct result | >0.6 |
| Tool-call count | Average calls to answer a question (context vs search+node loop) | context: 1, manual: 3-5 |
| One-call sufficiency | % of tasks answerable with a single context() or trace(source_mode=body) call | >60% |

## Running Benchmarks

Automated via the eval harness. Run:

```sh
CODECORTEX_WRITE_BENCHMARK=1 cargo test -p cc-eval -- benchmark_fixture
```

This executes a 3-run warm benchmark (1 warmup + 2 measured, take min) and writes results to `docs/benchmarks/latest.md`. Without `CODECORTEX_WRITE_BENCHMARK`, the test still runs but does not persist the report. Retrieval quality metrics are produced by `cargo test -p cc-eval -- integration_fixtures_and_corpus --nocapture`; current fixture coverage uses 8 `expected_symbols` cases.

For a non-fixture benchmark against this real workspace copy, run:

```sh
CODECORTEX_WRITE_REAL_BENCHMARK=1 cargo test -p cc-eval benchmark_real_workspace -- --ignored --nocapture
```

### Incremental Indexing Latency

The "<2s for 10 changed files" target is measured by three ignored scenarios over a synthesized 41-file TypeScript project (1 hub module + 30 importers + 10 standalone leaves):

```sh
cargo test -p cc-eval bench_incremental -- --ignored --nocapture
```

- `bench_incremental_noop` — zero-change rebuild (scan fast path + skip classification, no parse/resolve work).
- `bench_incremental_single_file` — one body-only edit (single re-parse, export fingerprint stable, no dirty propagation).
- `bench_incremental_dirty_closure` — export-surface change on the hub so all 30 importers are promoted Skip → DirtyResolveOnly via the dirty closure and re-resolved.

Each scenario runs 1 warmup + 5 measured incremental builds and prints p50/p95/max total latency plus the per-phase breakdown from `IndexReport.phase_timing` (scan_diff/parse/resolve/write/postprocess/analysis, dominant phase first). Report counters and the `dirty_propagation` status are hard-asserted (`normal` in all three scenarios; `budget_exceeded`/`partial_closure`/`disabled` would fail the run). The only latency gate is a generous p95 ≤ 2000ms sanity bound matching the target above — each scenario re-parses at most one file and re-resolves at most 30 importers, bracketing the 10-changed-files case; tighter relative assertions are intentionally avoided as flaky on shared hardware. A related ignored test, `benchmark_incremental_index_report_correctness`, covers the report counters across full → no-op → single-file builds without latency measurement.

Latest real-workspace run: 234 files, 10 representative MCP cases, all tools under 500ms p95; see `docs/benchmarks/real_workspace_latest.md`. Treat the fixture benchmark as a smoke baseline and the real-workspace benchmark as the current larger-repo regression baseline.

## Comparison Baselines

- grep/find loop: 5-10 tool calls per question
- context(task): 1 call, should cover 70%+ of symbol needs
- trace(source_mode=body): 1 call for full call-path with bodies
