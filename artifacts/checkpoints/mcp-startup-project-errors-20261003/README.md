## Counterexample and fix

`base-counterexample.rs` was injected only into the detached fixed-base worktree (mount diff: `base-injection.patch`). `base-counterexample.log` confirms the **old bug**, not acceptance: holding one permit on the real permissive singleton makes a legitimate 4/2 configuration return `CcError::Config` from `CodeIndex::new`. The old `ProjectSession::new` instead returns an empty active index, registers the requested path in both LRU/live identity, and returns `Ok` with that same empty Arc for the requested path. The actual `run_mcp_server` boundary proceeds to stdio and returns a transport error rather than Config. Original permit remains in flight and releases normally. No assumption about the unpublished review commit `75d32a6b…` was used.

Both public `new` methods now return `CcResult<Self>`. `ProjectSession` initializes `ProjectServices` with `?` before allocating cache/live/task ownership; the fallback-to-None/empty code was removed. MCP construction propagates that error, and `run_mcp_server` uses `?` before initial autoindex/watcher, idle, PPID watchdog or stdio service startup. The existing cold-path and set-active `?` ordering remains: only successful initialization/reopen publishes identities, and failed set-active leaves the original active view intact. `None` continues through `CodeIndex::new(None)` as a valid empty session.

The API signature change is deliberate. Every repository call site was audited: cc-eval's production backend uses `?` before creating duplex transport or spawning its MCP server, and direct test callers unwrap expected success. An infallible compatibility wrapper would preserve the production bypass, so none remains. External library callers must handle `CcResult` with `?` or an explicit error policy. Production ownership is limited to `project_session.rs`, `mcp.rs`, and the direct cc-eval constructor caller; remaining changes are necessary tests/call-site updates. Semantic runtime/wiring/queue/service factory/gate/core/DirectWriter bytes are unchanged from PR121.
