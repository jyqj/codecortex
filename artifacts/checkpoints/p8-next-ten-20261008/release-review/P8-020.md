## 工具输入与真实性边界

Manifest 冻结 run ID、任务状态 commit、候选 source commit、候选完整输入摘要和每条记录的 commit / path / SHA256。Git 引用必须是 40 位完整 commit；读取仅限本地 Git 中已存在的常规文件，不自动 fetch，所有传输协议关闭。拒绝符号链接、树对象、遍历路径、浮动引用、重复记录、未知 profile / scope / coverage、格式错误和摘要漂移。

记录通过显式的对象键路径指向原 JSON 中的 status、candidate source 和 input digest。工具从原字节读取这些字段，不把外围索引中的“通过”描述当作原始执行终态。没有对应字段时保留 unavailable；不会从工作树 HEAD、源码审查或 archive 索引猜测 binary 执行来源。

候选摘要使用“按路径排序的紧凑 path→sha256 JSON、无尾换行”的固定口径。回执的 `source manifest` 文件摘要可能使用另一种 JSON 结构，必须标为 `opaque_record_sha256`：此时是 **not_comparable**，不是源字节不同，也不是相同。测试覆盖了数值相同但口径不同仍不能作为输入相等证明的情况。

所有记录默认仍是未经外部认证的仓库声明。即使输入把 192 个任务全部写成 done、给每个前置附上完整 `release_validation` / passed 纸面记录，工具也只输出 `not_accepted` / 1。它没有运行候选源码完整性 gate、scorer、统计比较、raw 重放、provider、预算权威或正式发布审批。这些外部项始终保留，不提供信任开关。

JSON 单文件最多 2 MiB，最多 128 条证据、总证据最多 16 MiB，每个 Git 子进程最多 20 秒。输出目录独占创建且不可覆盖；原 manifest 和读取到的证据 JSON 按原字节保存在 `metadata/`。工具不执行归档里的脚本、不解压归档、不运行模型、不改输入。
