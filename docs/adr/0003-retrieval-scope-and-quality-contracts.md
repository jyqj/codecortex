# ADR-0003：检索范围与质量验收契约

状态：提议，随本轮非 embedding 优化 PR 评审。

## 背景

文件预选曾把系统的猜测改写为 `SearchRequest.file_paths`，导致词法和图候选被
同一个早期瓶颈排除。与此同时，评测先丢弃没有符号名的输出再计算排名，可能将
第六个结果算成第一个。增加排序信号并不能修复这两种问题。

## 决策

保持七个 crate 的单向依赖、SQLite 权威索引、真实 MCP eval，不引入模型或远程
服务。改造接口边界而非再增加一层全能 manager。

**检索作用域分离。** 调用者提供的 file/path/language 是 hard scope，所有通道
和最终结果均需遵守。Preselect 只提供排序先验和有界 grep 扫描提示；lexical 和
structural graph retrieval 可从 hard scope 内独立补充候选。fallback recency
不能冒充语义限制。命中 metadata 记录版本化的 scope policy。

**符号到源码投影独立。** `symbol_chunks` 是不依赖数据库的区间策略：有完整
容器时选择最小容器，没有时选择分割符号的相交片段。调用图发现成功不能因为
长函数跨 chunk 边界而在结果投影时丢失。排序截断前使用稳定 tie-break；同一
lane 的重复候选只能投一次 RRF 票，仍消耗原位置。

**正负相关性方向显式。** SQLite BM25 的负分转换成单调有界 strength；FTS
UNINDEXED 字段权重显式为 0。单调性、原始 rank、重复票和长符号投影有独立测试。
本决策不宣称现有所有人工加分已经校准。

**分析阶段输入聚合。** `AnalysisInputs` 将不可变来源/扫描信息与可变解释收集器
分离，移除未使用的参数，减少调用顺序混淆；三阶段提交和 epoch 守卫不变。

**未知接口采取保守失效。** 未具备完整导出契约的语言不再把两个空指纹解释成
内容等价。沿 importer 与已绑定调用/引用的目标依赖做有预算的传播，继续暴露
不完整闭包状态。只有源码未变文件的 `parser_exact` 本地绑定保留，其余 resolver
状态清除并重算。它不等于一般意义上的语义依赖完备证明。

**评测与生产解耦。** manifest、原始调用观测、评分、配对比较是分开的构件。
原始观察可离线重放；错误不从分母消失；按文件和区间判断目标，按可见文本验证
证据。回归夹具和 held-out 数据显式区分，不给手工夹具制造统计显著性。

## 代价与边界

全库词法候选可能增加查询开销；保守传播可能增加非 JS/TS 的增量成本。通过
既有规模测试和新增差分 oracle 验收，不为了保持历史速度掩盖漏召回或陈旧目标。
Grep 仍有 scope/扫描预算，不承诺完整全文扫描。全局名字桶、未绑定引用、未覆盖
关系、解析歧义、token 预算以及运行时反射仍有后续工作；这些边界应记录，不转换
成泛化能力分数。

## 验收

工作区 format/clippy/tests、既有 MCP 语料、新增身份/rank/单调性测试、MCP 质量
夹具及逐字节重放、增量/全量对照。生产基线和候选版本必须使用相同新 harness
与输入，分别隔离编译目录，原始结果随 CI artifact 留存。详细协议见
`../BENCHMARK_V2.md`。
