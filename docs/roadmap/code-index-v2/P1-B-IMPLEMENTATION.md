## 2. 必要的跨层修复

`symbol` 模式此前忽略已有的 path_prefix，本轮接入同一范围，过滤在 LIMIT 前完成；它没有因此获得新的 DSL。图补充证据既检查调用点，也检查邻居定义，避免返回路径看似在范围内而实际上引用被排除的目标。精确定位优先级是明确身份层，其后才按原重排分数与稳定ID排序；数值 score_trace 不虚增分数，也不能把跨层排序误称为单纯按分数降序。

GrepDiagnostics 随查询结果传递，不使用全局或线程状态。旧 Rust search() 保留命中数组接口，search_with_diagnostics() 返回命中和诊断且绕过结果缓存；MCP/图结果缓存保留诊断。complete 只证明 grep 游标耗尽；limited 代表候选上限；partial 代表扫描预算不足或预过滤错误，不能作为完整无答案的依据。解压额度不等于SQL总成本、全查询内存或延迟上限。

## 3. 测试与证据口径

入场摘要与P1-A证据一致；旧产品已保存到 `artifacts/benchmarks/p1b-20260927/binaries/codecortex-p1a`。有效红证据在 red-v2，覆盖近名路径、软提示、符号链接、缺失预算状态与精确目标被压制。初次编译错误、SQL夹具缺少父文件行、后来补充图见证测试受到解析器自环影响，均单独归类为测试准备问题，不作为生产失败或修复效果；见 evidence-classification.json。

图候选测试使用真实解析的符号与明确控制的邻接表，用于证明过滤/限额，不能充当解析器语义正确性证明。坏压缩块测试证明第cap+1块没有被解压；达到cap后只允许元数据探测。新原生路径用例明确拒绝不可表示的非UTF8/反斜杠文件名，并不宣称所有平台都支持这些名字。
