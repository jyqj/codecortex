## 解释边界与留存

HTTP request_enter_gap_ms 现在按 entered.time_ns 排序后计算。候选原 append 顺序有一次 timestamp inversion，最小 signed gap -2.713795ms；原 fixture 在 logging lock 前采样 entered timestamp，在锁内分配 sequence/追加，所以 append 顺序不等于时间戳顺序。原 signed 值保留为 request_enter_gap_append_order_diagnostic_ms，仅用于诊断日志顺序；不解释成负到达间隔。此时间戳晚于 body read，排序结果也不是 socket arrival spacing。raw 日志未改。

deadline 快照是独立只读 SQLite observation，保留实际 query/read 时间；未冒称恰好300.000000s。超过 deadline 的响应不接受为 ready，失败 tail 的额外 manifest 不变成通过。失败 EOF cleanup 与 post-ready 正常退出分开。正常 API EOF 和 integrity/FK 检查不构成 GC/WAL crash 证明。

RSS 为原20ms非原子采样，不是精确峰值/PSS。children 不可读则完整进程树 RSS unknown；observable sum 不冒充 full tree。cgroup current 包含 harness、build及page cache，不作产品 RSS。首次 Product 和 reopen 的原 raw resource logs 均保留；主表 lifetime 值描述首次 Product，reopen logs 单列，不合并不同 PID 的 lifetime counters。

无真实/付费 provider、heldout、GCWAL kill/crash/fault、EROFS testcase 或宽泛 runtime 组；无 fsync/cachelayout/SQL/预算/产品/CI 修改或循环调参。build/measurement 每项一次，历史失败只读保留。
