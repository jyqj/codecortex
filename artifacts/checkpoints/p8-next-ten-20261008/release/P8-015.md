# P8-015：semantic 发布证据的本地准入预检

本轮交付 `scripts/p8_semantic_certification.py`，用于严格检查本地材料完整性和跨记录一致性。**真实 semantic 发布认证没有完成，原 P8-015 不记为 done**。工具不调用模型、不联网、不运行候选 binary / scorer，也不读取 heldout 正文。当前版本任何路径均不能输出发布通过证书：材料缺失或不合格为 `blocked` / 非零退出，纸面材料结构齐全仍因外部真实性未验证而 `blocked` / 退出 1。

## 为什么结构通过后仍阻断

本地 JSON 的 `live_provider_export`、`clean`、`approved=true` 和 `deterministic_gold_scores` 都是提交者提供的声明。文件哈希能够确认字节及绑定关系，没有证明 provider 真正执行、托管者独立、审批者有权授权或 scorer 真正从确定性 gold 算出分数。不能从这些声明制造模型收益或清洁 heldout 结论。

回执始终保留四项外部阻断：真实 provider 执行来源验证、独立 clean-heldout 托管验证、预算审批权威验证、确定性评分及统计 gate 的执行验证。没有 `trust=true`、`allow_fixture` 或 `release_certified=true` 之类的绕过开关；未知字段直接拒绝。这一阶段的正控只检验本地结构准入，不构成真实认证的正例。

`local_profile={status:not_assessed,modified:false}` 明确限定影响。旧 local candidate 的流程不变；把 `p8_local_candidate` 当 semantic input lock 提交会阻断 semantic 宣称，也不会撤销或改写 local profile。

## 固定输入与七类证据

顶层 manifest 包含 schema 1、run ID、固定 provider / model / revision、阈值、binding 与 records。每个 record 使用相对文件路径和原字节 SHA256。binding 的九项为：40 位 source commit，binary、config、scoring、input lock、corpus、query、gold、case-set 的 64 位 SHA256。Input lock 自身的 binding 不包含其自身哈希，避免递归自哈希；其他记录必须与完整 binding 一致。

| record | 本地检查 |
| --- | --- |
| `input_lock` | semantic 专用 kind、实际 lock 摘要、模型身份，以及 binary/config/scoring 的实际文件 SHA256；config 继续执行原 helper 的敏感字段检查 |
| `custody` | clean-heldout 声明、独立来源标签、开发重叠数必须为 0、唯一 case 清单、清单摘要、最小样本数和托管记录哈希 |
| `execution` | run/model 一致、每个 request 的观测 revision、请求/响应摘要、起止时间、声明的公网 HTTPS 来源、唯一请求 ID 和 index/query/retry 阶段 |
| `attempts` | baseline / semantic 每 case 恰一条尝试、完整配对、已知终态、非布尔非负微秒、请求关联完整性，以及各 profile 全尝试错误分布 |
| `costs` | 所有请求（含 index/retry）的费用账本；严格区分 reported、estimated、unknown；金额使用十进制字符串 |
| `budget` | 固定 run/model/currency、明确批准布尔值、审批记录摘要、执行窗口、请求数与已报告费用上限 |
| `quality` | 固定 scorer 摘要、完整唯一 case 对、范围 0–1 的有限分数，重新计算成对均值差与声明阈值 |

每份 JSON 上限 2 MiB；binary/config/scoring 单文件读取上限 64 MiB。拒绝重复 key、符号链接、遍历路径、缺失文件、摘要漂移、浮动模型版本、非法费用格式及布尔型计数。受原路径规则限制，custody 只提供元数据文件（示例名称 `custody.json`），不把 heldout 正文路径交给开发预检。

费用为 reported 时要求 receipt SHA256，但这个 SHA256 仍不证明收据真实性。estimated 单独合计；unknown 不允许伪造金额或收据；漏记任一请求、只有估算或未知成本都不能通过费用门槛。请求计数包含索引和重试，不只统计最终成功查询。

`partial`、`timeout`、`tool_error`、`protocol_error`、`cancelled` 都留在全尝试分母中；缺失耗时不会补成 0。`no_match` 是终态成功，不代表质量提升。分数均值只是对提交行的算术复算；回执始终标明 scorer 未认证、统计验收未运行、模型收益未认证。

## 运行与退出语义

```bash
python3 scripts/p8_semantic_certification.py \
  --manifest /path/to/manifest.json \
  --output /tmp/p8-semantic-admission-new
```

输出目录独占创建；不覆盖历史回执。元数据原字节复制到 `metadata/`（CLI 创建为 0700 目录 / 0600 文件），回执保留 manifest 和每份材料的实际哈希、检查项目、错误分布、费用拆分及预算比较。不复制候选 binary/scorer 或读取 heldout 正文。失败时已保存材料保持可审查。

| 结果 | 退出码 | 含义 |
| --- | --- | --- |
| `structural_status=incomplete` | 1 | 必需材料缺失；semantic 阻断 |
| `blocked_local_candidate` / `failed` | 1 | local/fake/漂移/费用预算或其他一致性检查失败；semantic 阻断 |
| `structural_status=passed` | 1 | 文件和字段一致；外部真实性及统计验证仍未完成，semantic 阻断 |
| `status=invalid_input` | 2 | 格式、路径、文件摘要或严格类型校验失败；不构成认证 |

任何成功的结构检查都不能替代 P8-013、P7-018 或父 gate 的要求。调用方应检查进程退出码和 `M4_semantic`，不能只读取 `structural_status`。
