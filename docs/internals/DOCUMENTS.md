# Current document manifests and source freshness (P4-C)

## Identity and reuse

`DocumentRef` separates index-local `doc_key`, immutable `doc_version`, optional snapshot-qualified `entity_key`, and optional `encoding_key`. The owning IndexDb is an essential part of every reference; these hashes are not globally unique repository namespaces or authorization tokens. `chunk:<path>:<ordinal>` remains the wire/FTS mapping, not publication authority.

Key v1 conservatively anchors an exact original slice by canonical path, document kind, slice digest and duplicate occurrence. An unchanged slice can keep a key after a top insertion; altered slicing may create new keys. Duplicate occurrence and snapshot-qualified entities are not semantic lineage or rename guarantees. Rename produces removed/new mappings. Version v1 covers the source snapshot and span, owner/signature evidence, kind, actual chunk policy, encoding specification, complete rendered input or explicit render failure. Equal model bytes plus equal encoding spec may be reuse candidates while retaining separate source records. A changed source location may change version without changing encoding input. No vector is published by these APIs, and no cross-rebuild asynchronous publication or persisted incarnation guarantee is added here; those remain P6.

## Projection and storage

The existing parse task supplies exact bytes to `documents::delta::prepare`; no additional parser or disk read occurs for projection. Its typed `DocumentBatch` travels in FileWriteUnit/PreparedBuild through existing full staging and incremental transactions. The fixed current encoding spec contains document/render versions, RenderOptions and the explicitly estimated token-count convention. Every parsed file stores a separate `document_spec` stamp in the same files transaction. The stamp participates in file-state aggregation/cache validity and scan decisions, so a renderer-spec change cannot silently reuse old projections. Such a change conservatively reprocesses source in this version; syntax-free re-projection optimization is not claimed.

`document_manifest` is the current *indexed* mapping only, not history, a journal, outbox, vector artifact store or a statement that files still exist on disk. Each record stores bounded model input as well as provenance and a compact reference. A chunk deletion removes its manifest row through a foreign key plus an explicit delete trigger for existing full-stage connections with foreign keys disabled. Failed inserts roll back files, chunks and FTS under the existing transaction. DirtyResolveOnly leaves chunks and their manifests unchanged. Full and incremental builds use the same record format; `DocumentChanges` summarizes projected files only, not all index documents or removed-file counts. Delta records describe replacements/removals for a prepared file; deletion of whole files is handled by the storage transaction.

Rendering can fail under a too-small model-input budget while original source remains valid. Such a manifest has `input=null`, a render error and no encoding key; the index does not delete that source chunk. Empty files have a spec stamp and zero source documents. No provider or network request is made. Keeping actual model inputs aids auditable reuse but increases prepared-memory, storage and hydration cost; release mechanism observations do not constitute RSS or production throughput certification.

## Retrieval and safe source reads

The normal FTS mirror continues indexing original chunk text. Hydration validates the stored record against the exact chunk and rejects malformed or missing required manifests; public metadata adds `document`. Legacy/synthetic records can omit document identity but are never promoted into verified current source merely for compatibility.

Low-level SearchEngine returns indexed-snapshot facts with `disk_checked=false`. Public hybrid context search independently verifies candidate files on each call, including cache hits, then clones accepted hits and marks them `current_verified`. Changed/deleted/unavailable/over-budget files are omitted with `source_freshness.partial=true`; it does not refill beyond the original top-k, and omissions cannot masquerade as a successful no-answer. The evaluator public-v5 retains the source-partial distinction introduced in public-v4 and also validates lane receipts; partial/error/timeout/cancelled lanes cannot become a successful no-answer. Old binaries without lane receipts remain supported, but historical recorded runs require their matching adapter version. Byte-proof verification and legacy evidence validation remain strict. All 14 tool input contracts remain unchanged.

Symbol source, exploration and code-region reads use the same hash-checking reader before applying indexed coordinates. Stale results contain null source and an explicit diagnostic. Trace/flow snippets omit unsafe source and carry freshness diagnostics; remaining graph identities describe indexed analysis, not an atomic live compiler view. Display-normalized/line-numbered snippets are labelled and must not be confused with raw source proof.

Disk reads preserve exact path spelling and existing in-root symlink behavior; resolution cannot escape the project, and bounded descriptor-based reads reject special files and symlink substitution on the resolved path. This is not protection against hostile mounts, hardlinks or replacement of the trusted root. Source reads are bounded at 16 MiB/file; public hybrid verification uses a per-call 64 MiB charged budget and 128 file cache, not a persistent disk-state cache. The low-level bounded reader may read one sentinel byte to detect growth. Directory/name probes and source-read time are additional costs, not counted as SQL cost or eliminated by an index LRU hit. Small observation windows and per-file generation rechecks are not a single filesystem/global query snapshot; a file can change after successful verification.

Output truncation remains explicit. Metadata-heavy context envelopes retain bounded per-file reference/reason previews and the existing human source rendering instead of an arbitrary JSON prefix; this does not alter ranks, raise output budgets, or certify incomplete machine evidence. Both resolution and source freshness are preserved outside the preview. The full serialized hard-output budget redesign remains P5.

Schema 21 and file-state aggregate format 5 require isolated rebuild from schema 20 or older. ProjectModel remains version 3. Do not test migration against the developer's daily index. Prior accepted binaries, source-hash receipts and all failed observations remain retained; hashes alone are not source backup archives. G4, provider workers, durable document history, public holdout, 100k/peak memory/tail latency, cross-platform and release certification are not implied.
